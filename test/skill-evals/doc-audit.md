# Elixir skill documentation audit

Checked September 5, 2026. Repository skill files remain unchanged.

Official documentation checked includes Elixir 1.20.4, Ecto 3.14.2, Ecto SQL 3.14.0, Phoenix 1.8.13, LiveView 1.2.11, Plug 1.20.3, Oban 2.24.1, and Oban Pro. The unversioned Pro documentation currently serves 1.8.0-rc.1. Stable Pro 1.7.10 documentation was checked separately for workflow and batch behavior. Installed project versions must take precedence over these documentation defaults.

## Claims that need narrower wording, not invented certainty

- The CTE prefix rule is too broad. Current Ecto documents schema-prefix inheritance when selecting a CTE through a schema tuple and uses prefix: nil to override it. Parent-query, source-schema, and CTE-reference prefixes are separate concerns. Do not prescribe setting every recursive query to a tenant prefix without checking the generated SQL. [CTE documentation](https://ecto.hexdocs.pm/Ecto.Query.html#with_cte/3).
- The 10x join-preload memory claim has no workload or benchmark attached here. Explain row multiplication only if that changes the task, without inventing a universal multiplier.
- PostgreSQL rejects NUL in character values. This is not a PostgreSQL server crash, and silently removing characters is a data-policy choice. [Character types](https://www.postgresql.org/docs/current/datatype-character.html).
- LiveView mount/handle_params, patch navigation, connected-only async startup, and assign_new reuse are broadly documented correctly. Starting async work need not wait for mount to return. Parent assign sharing has lifecycle conditions. [LiveView lifecycle](https://hexdocs.pm/phoenix_live_view/Phoenix.LiveView.html#module-life-cycle), [assign_new](https://hexdocs.pm/phoenix_live_view/Phoenix.Component.html#assign_new/3).
- Uniqueness guarantees and bulk-insert support depend on the configured engine and version. Avoid generalizing Basic behavior to Pro or using uniqueness as an exactly-once execution guarantee. [Current uniqueness guide](https://oban.hexdocs.pm/unique_jobs.html#unique-guarantees), [current Pro engine](https://oban.pro/docs/pro/Oban.Pro.Engine.html#module-enhanced-unique).
- The run_workflow example's completed-count summary is supported by the current default behavior. Keep the requirement for manual workflow testing. Append also exists, but dependency validation depends on which jobs are supplied. [Testing API](https://oban.pro/docs/pro/Oban.Pro.Testing.html#run_workflow/2), [append](https://oban.pro/docs/pro/Oban.Pro.Workflow.html#append/2).

## Revised editing approach

First remove incorrect constraints and repair examples. Then remove duplicated warnings and tutorial material that adds no task-specific decision. Keep the user's explicit unbuffer and verification preferences. Add a compact instruction to consult installed-version dependency rules and documentation.

Documentation establishes API correctness, not whether Astra reliably makes the right decision without the skill. No controlled with/without-skill evaluation was run in this audit. Claims that a borderline section is redundant remain hypotheses until tested on representative tasks. There is no evidence-based target line count.


## Oban Pro recheck

Rechecked September 5, 2026 after the user questioned the earlier claim. The stable release page lists 1.7.12, while the unversioned docs serve prerelease 1.8.0-rc.1. The earlier check of 1.7.10 was version-pinned but did not cover the newest stable patch. [Stable release history](https://oban.pro/releases/pro/v1.7).

The [1.7.12 Worker docs](https://oban.pro/docs/pro/1.7.12/Oban.Pro.Worker.html) and [1.8.0-rc.1 Worker docs](https://oban.pro/docs/pro/Oban.Pro.Worker.html) still document `process/1` for `Oban.Pro.Worker`. Optional `args_schema` casts persisted args into the worker's struct at execution. Without that schema, Pro does not automatically make every job's args a worker struct. The actual error in our recording example is its `perform/1` callback.

The earlier wording grouped recorded output with incorrect examples too broadly. Our existing `recorded: true` option and `{:ok, value}` return are valid for an ordinary recorded Pro worker. Recording can also be configured with keyword options. Pro 1.8 adds global recording defaults and external output storage, so a literal `recorded: true` declaration on each worker is not universally required. [1.8 changelog](https://oban.pro/docs/pro/changelog.html#global-worker-defaults).

Workflow cascade functions automatically record their results, excluding control tuples such as error, cancel, and snooze. That is another reason to avoid a blanket rule requiring every workflow step to declare recording. [Workflow.add_cascade/4](https://oban.pro/docs/pro/Oban.Pro.Workflow.html#add_cascade/4).

The frozen evaluation snapshots retain the earlier overbroad recording wording as historical experiment inputs. The six executable cases use public Oban and do not test Pro workers or recordings. Their passing results provide no evidence for those Pro claims. Production skill edits remain a proposal.
